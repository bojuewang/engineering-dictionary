# Engineering terms

Bilingual working definitions for this repository; these are explanatory definitions rather than quotations from a formal standard.

| Term | 中文 | Working definition |
| --- | --- | --- |
| Architecture | 架构 | Fundamental organization of a system, its components, and their relationships. |
| Specification | 规格说明 | Explicit requirements and constraints that an implementation is expected to satisfy. |
| Protocol | 协议 | Agreed rules for interaction, communication, or execution. |
| Standard | 标准 | A documented set of requirements or conventions established for consistent use; its authority depends on its adoption or issuing body. |
| Convention | 约定 | A commonly used or locally agreed practice. |
| Configuration | 配置 | Settings that determine behavior without necessarily changing the underlying implementation. |
| Metadata | 元数据 | Data describing another resource, object, or dataset. |
| Schema | 模式 | A description of permitted data structure and constraints. |
| Manifest | 清单 | A declaration of included resources, components, or relevant properties. |
| Namespace | 命名空间 | A scope in which identifiers are interpreted and distinguished. |
| Identifier | 标识符 | A name or token used to identify an entity within a scope. |
| Interface | 接口 | A defined boundary through which components interact. |
| Implementation | 实现 | A concrete realization of a specification or design. |
| Workflow | 工作流 | An organized set of activities and dependencies used to produce an outcome. |
| Pipeline | 流水线 | A sequence of processing stages, often passing each stage's output to the next. |
| State | 状态 | Information describing a system or object's condition at a particular point. |
| Artifact | 工件 / 产物 | A produced or maintained item such as a document, dataset, executable, or certificate. |
| Repository | 仓库 | A managed collection of resources, often with version history. |
| Version | 版本 | An identified revision or release of a resource. |
| Validation | 有效性确认 | Assessment against intended use or user needs; some contexts use this term for checking data constraints. |
| Verification | 验证 | Assessment of whether specified requirements are satisfied. |
| Template | 模板 | A reusable structure used to produce consistent instances. |

## Important distinctions

- Architecture describes organization; specification defines requirements; implementation realizes them.
- Schema constrains structure; metadata describes resources; a manifest declares their contents or properties.
- Protocol defines interaction rules; workflow organizes activities; a pipeline is a stage-oriented processing arrangement.
- Verification checks specified requirements; validation considers intended use (terminology can vary by domain).
